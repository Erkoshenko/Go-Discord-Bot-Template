# Template-Go-Discord-Bot

Шаблон расширяемого Discord-бота на Go (discordgo + PostgreSQL). Рассчитан на то, что бота будут наращивать модулями: модерация, экономика, тикеты и т.д.

За основу взят [golang-standards/project-layout](https://github.com/golang-standards/project-layout): `/cmd` — запуск, `/internal` — код приложения, `/pkg` — код, который можно переиспользовать в других проектах.

## Быстрый старт

1. Скопируйте `.env.example` в `.env` и вставьте токен бота.
2. Поднимите локальную базу: `docker compose up -d`.
3. В `configs/config.yaml` укажите `test_guild_id` (ID вашего сервера): команды появятся на нём сразу. Если пусто, команды регистрируются глобально и обновляются до часа.
4. Запустите: `go run ./cmd/bot`.

## Как это устроено

```
cmd/bot/main.go            запуск, остановка, перезапуск
        │
        ▼
internal/app               App: собирает всё вместе
        │   ├─ database    пул соединений Postgres
        │   ├─ repository  ОБЩИЕ репозитории (users)
        │   └─ modules     список включённых модулей (app/modules.go)
        ▼
internal/<модуль>          самостоятельная функция бота
   ├─ commands   слой Discord: аргументы, права, ответы
   ├─ service    бизнес-логика
   └─ repository данные этого модуля
```

Зависимости идут сверху вниз. Модули не импортируют друг друга: общее у них только `internal/repository` (общие данные), `internal/module` (контракт) и `internal/commands` (каркас команд).

### `/cmd/bot`

Только управление жизненным циклом, бизнес-кода здесь нет.

- читает `.env` и `configs/config.yaml`, создаёт `App` и запускает его;
- **Ctrl+C / SIGTERM** — корректная остановка (сначала закрывается Discord, потом база);
- **SIGHUP** — перезапуск: `.env` и `config.yaml` читаются заново (Linux/macOS: `kill -HUP <pid>`);
- любой модуль может сам попросить перезапуск через `Deps.RequestRestart()`.

### `/internal/app`

`App` собирает бота: подключает базу, создаёт общие репозитории, создаёт и инициализирует модули, собирает команды всех модулей в один реестр, создаёт сессию Discord с нужными интентами и запускает её.

- `app.go` — сборка и `Run(ctx)`.
- `modules.go` — **единственное место, где включаются модули.** Хотите отключить модуль — удалите его строку.

### `/internal/module`

Контракт модуля (`module.Module`): `Name`, `Init` (создать таблицы), `Commands`, `Intents`, `Register` (подписаться на события Discord). Встройте `module.Base`, и необязательные методы можно не писать. `module.Deps` — то, что `App` даёт модулю: база, общие репозитории, настройки, логгер, `RequestRestart`.

### `/internal/commands`

Каркас слэш-команд: интерфейс `Command` и `Registry` (регистрация в Discord, поиск нужной команды, защита от паники, ответ «что-то пошло не так»). Самих команд здесь нет: каждая команда живёт в своём модуле. Кнопки, модалки и автокомплит модуль обрабатывает сам через `Register`.

### `/internal/repository`

**Общие** репозитории: данные, нужные нескольким модулям (пользователи, баланс). Данные одного модуля лежат в самом модуле.

- `container.go` — структура `Repositories`, конструктор и `CreateTables` (вызывается из `App`).
- `user_repo.go` и другие `<сущность>_repo.go` — интерфейс и его реализация на Postgres. По интерфейсу в тестах подставляют заглушку (примеры в `/examples`).

Правила: только SQL, никакого `discordgo`; конструктор принимает `*pgxpool.Pool`; ошибки оборачиваются через `fmt.Errorf("...: %w", err)`; «строки нет» (`pgx.ErrNoRows`) обрабатывается здесь, а не в командах.

Новый общий репозиторий: файл `<сущность>_repo.go`, поле в `Repositories`, создание в `NewRepositories`, строка в `CreateTables`.

### `/internal/database`

`Connect` создаёт пул соединений Postgres и проверяет связь. Запросов к таблицам здесь нет. Пул создаётся и закрывается в `App`, глобальных переменных нет.

### `/internal/config`

`config.Load` читает несекретные настройки из `configs/config.yaml` и секреты из окружения. Настройки модуля — отдельная структура в `settings.go` (пример: `Moderation`).

### `/internal/moderation` — готовый модуль-пример

Команды `/warn`, `/warns`, `/unwarn`, `/timeout`, `/kick`, `/ban`. Показывает, как выглядит модуль целиком:

| Файл | Слой | Что внутри |
| --- | --- | --- |
| `module.go` | сборка | `New`, `Init`, `Commands`, `Register` |
| `commands_*.go`, `checks.go` | Discord | аргументы, права, иерархия ролей, ответы |
| `service.go`, `messages.go` | бизнес-логика | правила, порядок действий, автомут при `warn_limit` предупреждений |
| `gateway.go` | Discord API | мут, кик, бан, личные сообщения, журнал (интерфейс, чтобы тестировать без Discord) |
| `repository.go`, `models.go` | данные | таблица `moderation_cases` и запросы |
| `service_test.go` | тесты | пример теста логики с заглушками |

Настройки в `configs/config.yaml`, раздел `moderation`: `log_channel`, `warn_limit`, `warn_timeout_minutes`.

Права команд заданы и в Discord (`DefaultMemberPermissions`), и проверяются в коде. Боту нужны права «Исключать участников», «Банить участников», «Управлять участниками», а его роль должна быть выше ролей наказываемых.

### `/internal/general`

Базовые команды (`/ping`). Самый маленький пример модуля.

### `/examples`

Примеры для разработчика, не часть бота; удаление не повлияет на работу.

- `mock_example.go` — заглушка репозитория вместо базы.
- `repository_test_example.go` — пример теста репозитория. Go запускает только файлы `*_test.go`, поэтому скопируйте его рядом с проверяемым кодом и переименуйте.

### `/configs`, `/pkg`

`/configs` — настройки по умолчанию. `/pkg/respond` — помощник для ответов на команды, не привязанный к конкретному боту.

## Как добавить новый модуль

1. Создайте папку `internal/<имя>` (например, `internal/economy`).
2. В `module.go`: структура со встроенным `module.Base`, конструктор `New(d module.Deps)`, метод `Name()`. Остальное по необходимости: `Init` (таблицы), `Commands`, `Intents`, `Register`.
3. Если нужны данные только этого модуля, положите репозиторий (интерфейс + Postgres) в папку модуля. Если данные общие (пользователи), используйте `d.Repos`.
4. Бизнес-правила — в `service.go`, команды — в `commands_*.go`. Команды вызывают сервис, сервис вызывает репозиторий.
5. Если нужны настройки, добавьте структуру в `internal/config/settings.go` и раздел в `config.yaml`.
6. Добавьте `economy.New(d)` в `internal/app/modules.go`.

## Где что лежит

| Что вы пишете | Куда класть |
| --- | --- |
| Новая функция бота | `internal/<модуль>/` + строка в `app/modules.go` |
| Слэш-команда | `internal/<модуль>/commands_*.go` |
| Бизнес-правило | `internal/<модуль>/service.go` |
| SQL модуля | `internal/<модуль>/repository.go` |
| Данные, нужные многим модулям | `internal/repository/<сущность>_repo.go` |
| Реакция на событие Discord | `Register` модуля (`session.AddHandler`) |
| Настройка модуля | `internal/config/settings.go` + `configs/config.yaml` |
| Тест | рядом с кодом, файл `*_test.go` |
| Токен, пароли | `.env` (не в git) |

## `.env`

- `DISCORD_TOKEN` — токен бота. `DB_USER`, `DB_NAME` обязательны; `DB_HOST`, `DB_PORT`, `DB_SSLMODE` необязательны (по умолчанию `localhost`, `5432`, `prefer`).
- Файл не должен попадать в git (он в `.gitignore`). В репозитории лежит `.env.example`.
- Если токен когда-либо попал в публичный репозиторий, сбросьте его в Discord Developer Portal.
